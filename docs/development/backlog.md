# Беклог: відкладені низькопріоритетні пункти

Пункти, що не блокують поточну розробку. Джерело — рев'ю субагентами TCK-011…TCK-016 та
перевірки під час реалізації. Статус `BACKLOG` (див. `tasks.md`); пункти з позначкою
«рішення» потребують відповіді власника до реалізації.

## Потребують рішення власника

| ID | Тікет | Опис | Рішення |
|---|---|---|---|
| BL-01 | TCK-013 | Скасування побудови індексу при SIGTERM (cooperative stop-flag у `build_index`). Зараз зупинка чекає кінця побудови; задокументовано. | Чи вводити stop-flag, чи лишити + `stop_grace_period` |
| BL-02 | TCK-016 | Джерело тексту документа для snippet. **Вирішено:** перечитування з `DATASET_DIR` для top-K під час пошуку (пам'ять не подвоюється). | Закрито власником |
| BL-03 | TCK-013 | Приймати `threads` як ціле число у вигляді `4.0` (зараз `invalid_threads`). | Залишити як у специфікації чи розширити |
| BL-04 | TCK-017 | Режим `mode: "expanded"`. **Вирішено** за OQ-02: валідний, розширення через Ollama, збій — пошук без розширення (TCK-018/020). Лишається розбіжність у старому тексті 02, виправити текст. | Закрито; правка тексту 02 |
| BL-05 | TCK-017 | Пошук виконується в єдиному потоці `io_context`: ранжування і синхронне читання top-K файлів блокують інші запити (суперечить FR-028 / AC-028.1). Ризик для бенчмарків. | Виносити пошук у пул потоків (архітектура) чи зафіксувати як обмеження в ADR |
| BL-06 | TCK-004 / TCK-017 | Симлінки в датасеті: `entry.is_regular_file()` слідує за симлінком на файл, тож `/etc/passwd` через симлінк індексується. Читання тепер перевіряє межі каталогу, але політику індексації треба затвердити. | Пропускати симлінки в discovery (`skipped: symlink`) чи дозволяти |
| BL-07 | TCK-017 | `MAX_QUERY_LENGTH` рахує байти, а 06 і BDD говорять про символи (кирилиця вдвічі «довша»). | Зафіксувати «байти» чи рахувати кодові точки (OQ-06) |
| BL-08 | TCK-017 | Snippet порожній, якщо файл недоступний; це відхилення від FR-015 («містить терм»), задокументовано. | Прийняти як відоме обмеження чи додати фолбек |
