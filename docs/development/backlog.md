# Беклог: відкладені низькопріоритетні пункти

Пункти, що не блокують поточну розробку. Джерело — рев'ю субагентами TCK-011…TCK-016 та
перевірки під час реалізації. Статус `BACKLOG` (див. `tasks.md`); пункти з позначкою
«рішення» потребують відповіді власника до реалізації.

## Потребують рішення власника

| ID | Тікет | Опис | Рішення |
|---|---|---|---|
| BL-01 | TCK-013 | Скасування побудови індексу при SIGTERM (cooperative stop-flag у `build_index`). Зараз зупинка чекає кінця побудови; задокументовано. | Чи вводити stop-flag, чи лишити + `stop_grace_period` |
| BL-02 | TCK-016 | Джерело тексту документа для snippet: пам'ять (подвоєння 1 ГБ) або перечитування з `DATASET_DIR`. Блокує TCK-017. | Вибір варіанта |
| BL-03 | TCK-013 | Приймати `threads` як ціле число у вигляді `4.0` (зараз `invalid_threads`). | Залишити як у специфікації чи розширити |

## Низький пріоритет

| ID | Тікет | Опис |
|---|---|---|
| BL-10 | TCK-013 | Захоплення виконавця сокета до виклику побудови (зараз копіюється `self` у callback; безпечно за поточного життєвого циклу). |
| BL-11 | TCK-014 | `stats_provider_` без значення мовчки повертає нулі; краще 500 `internal_error`. |
| BL-12 | TCK-014 | Недосяжна гілка `internal_error` для `/api/stats` у `route()`. |
| BL-13 | TCK-016 | Тест, що падає без `utf8_safe_end`; нормалізація регістру термів на вході snippet (зараз вимога — вже токенізовані терми). |
| BL-14 | TCK-012 | L1: деструкція великого індексу під `mutex_` (мінімізувати час утримання замка). |
| BL-15 | TCK-012 | L4/L5: тести станів Building/Rebuilding без детермінованого блокера; очищення `last_error` при старті побудови. |
| BL-16 | TCK-005…TCK-008 | Низькі пункти рев'ю: парсер `OLLAMA_URL`, роутер для кількох реалізованих маршрутів, тест колізій `TermTable`, Cyrillic Extended, UTF-8 тести, фолбек `is_token_char`, `doc_id` не в UTF-8. |
