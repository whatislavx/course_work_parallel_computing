Зв'язок обмежень і NFR: CON — джерело (що вимагає завдання або власник), NFR — перевірна форма: CON-005/006 → NFR-013; CON-007 → NFR-012; CON-010 → NFR-017; CON-011 → NFR-014; CON-014 → NFR-015; CON-003/004/015 → TEST-DOC-08, TEST-DOC-10.

Що дозволено (не порушує CON-003/CON-004/CON-015): бібліотеки HTTP/WebSocket-сервера, JSON, HTTP-клієнта, тестовий фреймворк — як допоміжна функціональність (`CLAUDE.md` §11). Кожну таку бібліотеку затверджує власник (`CLAUDE.md` §5). Внутрішні потоки HTTP-бібліотеки для обробки з'єднань не замінюють власний пул побудови індексу; чи допустимо використовувати їх для паралельної обробки запитів — OQ-29.

## 3. Інтеграція з Ollama

| Аспект | Значення | Статус |
|---|---|---|
| Протокол | HTTP/1.1, JSON | Факт (Ollama API) |
| Адреса | `OLLAMA_URL` (пропозиція: `http://ollama:11434` у мережі compose) | P |
| Генерація | `POST /api/generate` з полями `model`, `prompt`, `stream: false` (пропозиція — без стрімінгу, щоб отримати одну відповідь) | SRC-A (ендпоінт), P (поля) |
| Модель | `OLLAMA_MODEL` | OQ-13 |
| Промпт | Інструкція повернути список англійських ключових слів і синонімів для запиту, у машинно-розбірному форматі | P, OQ-14 |
| Розбір відповіді | Поле `response` → виділення слів → нормалізація (OQ-21) → видалення дублікатів і термів запиту → обрізання до `MAX_EXPANDED_TERMS` | P (FR-019) |
| Тайм-аут | `OLLAMA_TIMEOUT_MS` | OQ-14 |
| Перевірка доступності | Пропозиція: `GET /api/tags` і наявність `OLLAMA_MODEL`, тайм-аут `HEALTH_CHECK_TIMEOUT_MS` | OQ-13 |
| Одночасні виклики | Кожна WS-сесія робить власний виклик; окремого обмеження викликів Ollama немає, загальне обмеження — `MAX_CONCURRENT_CONNECTIONS` (NFR-025) | P, OQ-30, OQ-35 |

### 3.1. Поведінка при збоях

| Збій | Поведінка | Вимога |
|---|---|---|
| З'єднання відхилено / DNS | fallback, `expanded_terms: []`; health `ollama: false` | FR-021, FR-002 |
| Тайм-аут | fallback після `OLLAMA_TIMEOUT_MS` | FR-021, NFR-020 |
| HTTP-код ≠ 200 (у т.ч. модель відсутня) | fallback | FR-021 |
| Відповідь не JSON / немає `response` / немає придатних слів | fallback | FR-021 |
| Повільна відповідь | не блокує інших клієнтів | NFR-007 |

Кожен збій логується з типом збою, без повного тексту запиту користувача (NFR-021 — пропозиція мінімізації).

## 4. Docker Compose і середовище виконання

| Аспект | Вимога | Статус |
|---|---|---|
| Сервіси | пошуковий сервер, Ollama | CON-007 |
| Додаткові сервіси | лише з затвердженим обґрунтуванням (статичний веб-сервер — OQ-15; ініціалізація моделі — OQ-13) | NFR-012 |
| Мережа | спільна мережа compose; сервер звертається до Ollama за іменем сервісу | P |
| Порти назовні | порт сервера (REST, WS, UI); порт Ollama — опційно | P |
| Томи | модель Ollama (постійний); датасет (read-only) | P, OQ-23 |
| Готовність | контейнер «запущено» ≠ сервер готовий; готовність визначає `/api/health`, готовність моделі — `ollama: true` (NFR-024) | `.claude/rules/architecture.md` §12 |
| Завершення | `docker compose down` надсилає SIGTERM; сервер завершується коректно (NFR-026) | P |
| Ресурси | ліміти CPU/RAM контейнера фіксуються у звіті бенчмарку, бо впливають на T(p) | NFR-023 |
| ОС хоста | Linux / macOS / Windows з Docker Desktop | ASM, P |

## 5. Конфігурація

Перелік параметрів — NFR-019 і 06 §2.7. Вимоги:
- значення за замовчуванням для кожного параметра, крім тих, що позначені OQ;
- валідація при старті з помилкою і ненульовим кодом виходу;
- `.env.example` без секретів.
